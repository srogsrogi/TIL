# 공공 API 데이터 품질 검증

- 건축물대장 API로 주택유형 자동판정해주는 로직이 있는데 빌라를 아파트로 판정하는 오류 발생
- 백엔드 로직 오류일 거라고 생각했는데, API 데이터 자체의 오류가 있었음
- 층별개요 API의 주용도 필드 오류를 발견하고 전국 단위로 확장 검증해서 포털에 데이터 개선 요청까지 넣어본 기록



## 상황 요약

- 시작은 서울 강서구 화성빌라 한 건
- 내가 만든 `property_type` 자동 판정 로직이 이 건물을 APARTMENT로 오분류
  - 실제론 지상 4층 지하 1층 다세대주택
    - 건축법상 지상층만 5층 이상이어야 아파트
  - 표제부(getBrTitleInfo)는 `mainPurpsCdNm="공동주택"` + `etcPurps="다세대주택"` 으로 정상
  - 그런데 층별개요(getBrFlrOulnInfo)는 전 층 `mainPurpsCdNm="아파트"`로 와버림
- 주택유형은 판정오류 발생 가능성이 있어 사용자가 직접 수정할 수 있도록 열어두긴 했지만, 사용자도 모르고 넘어가면 이후 기능 이용 시 문제가 발생할 수 있어 중요한 이슈
- 그럼 얼마나 많은 건물이 이렇게 틀려 있는지 파악해야 했음



## 검증 배경

- 이 건물만 이럴 것 같지는 않고.. 같은 패턴의 신규 건물에서 또 터질 것
- 그냥 사용자한테 "주택 유형 네가 알고 있는 거랑 맞는지 한 번 더 확인해라."라는 안내문구 띄워주는 정도로 끝낼 수도 있긴 한데..
- 그런 식이면 자동판정 기능 자체가 의미를 좀 잃는 것 같아서 전국에 있는 건물 층화추출해서 문제 패턴 확인해보기로 함



## 검증 설계

| 후보 | 비용 | 신뢰도 |
| --- | --- | --- |
| 표제부 API (다른 오퍼레이션) | 싸다 (1 call) | 애매. 이것도 틀릴 수 있음(실제로 4건 그랬음) |
| 전유공용 API | 싸다 | 애매. 같은 DB |
| 세움터 건축물대장 PDF 원문 | 비싸다 (건당 수십 초 + 봇 필요) | 법적으로 확정된 원본 |

- PDF가 유일하게 신뢰 가능한 ground truth인데 시간이 오래 걸림

- API 비교로 후보군 최대한 좁히고, pdf로 2차검증 하는 방식으로 설계



## 1차 — API 간 교차 비교

### 가설

표제부 mainPurpsCdNm 과 층별개요 mainPurpsCdNm 의 **불일치 자체가 오류의 지문**일 것

- 같은 건물 같은 필드인데 두 엔드포인트가 다른 값 반환한다는 것부터 품질 이상의 징후



### 실행

- 국토부 실거래가 API로 전국 시군구 주소 38,945건 표본 층화추출
  - 전국 255개 시군구를 각각 독립 모집단으로 처리, 구당 최대 300건

- 이 중 표제부가 다세대·연립·도시형생활주택이면서 `mainPurpsCdNm=공동주택`인 11,209건 추림
- 이 11,209건 전부에 층별개요 API 재조회
- 층별개요에 `mainPurpsCdNm="아파트"`가 섞인 후보군 추출



### 한계

- 표제부랑 층별개요가 둘 다 틀려서 서로 일관된 케이스는 이 필터에 안 걸림
- 즉 "API끼리 일관성 있다=정답이다"가 아니긴 함



## 2차 — PDF 원문 대조

### 실행

- 후보 전부에 세움터 건축물대장 PDF 자동 발급 파이프라인 돌림
  - 이상 후보군 전부에 대해 우리 서비스 자동발급 기능 API 싹 호출해서 pdf 뽑음
  
- 받은 PDF 원문 vs API 반환값 1:1 대조
- **76건 오류 최종 확정** (11,209 대비 0.68%)
  - 자동화 주소 검색에서 도로명이 같은 건물 물어온 경우 등 우리 서비스 로직 오류로 인한 문제(5건)도 있었음. 이건 추후 픽스했고..




## 오류 패턴

- 확정된 76건을 들여다보니 성격이 두 갈래로 갈림.

| 타입 | 건수 | 특징 |
| --- | --- | --- |
| A | 72 | 표제부·전유공용·PDF는 일관되게 "비-아파트" → 층별개요 mainPurpsCdNm만 단독 "아파트" |
| B | 4 | 표제부까지 "공동주택"으로 틀려있음. PDF는 근린생활시설·복합용도·단독주택 — 양쪽 API 다 현실과 괴리 |

- 지역 분포

  - 서울 8, 부산 5, 대구 2, 인천 1, 광주 3, 대전 12, 경기 8, 충남 2, 전남 2, 경북 13, 경남 19, 제주 1

  - 창원시 진해구 12건 / 대전 대덕구 8건 / 포항 북구 5건으로 특정 지역에 몰려 있음
    - 특정 건축물대장 입력 담당자 실수거나 지자체별 시스템의 문제일 듯?




## 소감

- 일단 공공데이터포털에 개선제안 넣어봄
  - 건축물대장 원본(pdf) 관리는 각 지자체 건축과 소관이라는데, API는 누구한테 수정권한이 있는지 잘 모르겠음
  - 이것도 각 지자체에 권한이 있는 거면 포털에서는 어차피 수정 못 해줄 거고, 전수조사해서 수십 개 이상의 지자체에 각각 요청 넣어줄 것 같지는 않으니 제안했어도 그냥 반려당할 것 같기도 한데
  - 약간 오픈소스 기여하는 거랑 비슷한 느낌이라 해야 되나.. 암튼 재밌었음


- 꼭 이번 오류 아니어도 같은 대상에 대해서도 API나 문서끼리 다 원천 소스도 다르고 정규화 방식도 다르고(방식이 다른 정도가 아니라 그냥 정규화를 해놓지도 않은 놈들도 많음) 해서, 외부데이터 쓰는게 진짜 쉽지 않다는 걸 많이 느낌. 현실 데이터는 정말 더럽다.
